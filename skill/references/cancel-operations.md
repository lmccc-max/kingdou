## 取消功能（员工撤销发错的记录）

触发（员工在群里 @机器人 后发送，@ 会被网关自动剥离）：

```
取消 001          取消001        撤销 5
取消 001 002      作废 1-3       取消全部（仅审核员）
```

处理逻辑（`scripts/router/cancel_piecework.py`）：

| 条件 | 结果 |
|------|------|
| 员工取消**本人姓名**且状态为「待审核」的记录 | ✅ 取消成功 |
| 员工取消他人记录 | ❌ 提示「只能取消本人提交的记录」 |
| 取消「已通过 / 已拒绝」记录 | ❌ 提示已审核，需审核员用「拒绝」处理 |
| 重复取消（已是「已取消」） | ❌ 提示无需重复取消 |
| 编码不存在 | ❌ 提示未找到（兼容 001 / 1 / 056 等写法） |
| 审核员/管理员 | 可取消本群任意待审核记录，可用「取消全部」 |
| 非本群员工/无关用户 | 不处理、不回复，交给 AI |

取消为**软取消**（不物理删除，保留审计痕迹）：

- `审核状态` → `已取消 <时间>`
- `数量` → `0`（`金额` 公式 = 单价×数量 随之归零，不计入工资）
- `单价` → **保留原值不动**（便于事后追溯）
- `审核人` → 操作人姓名（来自 `openid_name_mapping`）
- `备注` → 操作人姓名（覆盖式留痕，非「已取消 原单价X…」格式）

生效范围：`待审核` 查询、`同意全部`、`今日工资` 都会自动排除「已取消」记录；
`query_salary.py` / `query-today-salary.py` 仅在有取消记录时追加 `🚫 已取消：N 条` 一行。

⚠️ **CANCEL 路由无论业务成功或失败都会拦截 AI**（脚本已发出权威提示消息），避免 AI 二次回复。
仅当发送者既不是本群员工也不是审核员时才返回 `ok=False`，放行给 AI。
